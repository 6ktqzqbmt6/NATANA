# NATANA 에이전트 사용 안내

이 폴더는 반복 사용할 역할 지침이다. NATANA 웹서비스는 선택한 역할의 지침을 서버에서 읽어 채팅 답변에 적용한다. 실제 이용에는 웹서비스 배포와 로그인·OpenAI 설정이 필요하다. Codex에서도 역할을 지정하면 해당 파일을 읽어 적용한다. 파일 자체가 독립 실행 서비스나 플랫폼 등록을 의미하지 않는다.

## 호출 방법

`브랜드 전략 에이전트로 진행해줘. 국내 20대 고객을 위한 포지셔닝을 제안해줘.`

자료, 원하는 결과물, 대상 시장, 기간·예산 등의 제약을 함께 주면 좋다. 여러 역할을 요청하면 필요한 순서로 검토하고 결과를 연결한다.

## 역할 목록

| 역할 | 지침 | 예시 요청 |
|---|---|---|
| 시장·트렌드 리서치 | [market-trends.md](market-trends.md) | 국내 20대 립 제품의 경쟁 가격과 구매 니즈를 조사해줘. |
| 브랜드 전략 | [brand-strategy.md](brand-strategy.md) | NATANA의 포지셔닝 대안을 비교해줘. |
| 상품 기획 | [product-planning.md](product-planning.md) | 첫 색조 라인업의 제품 기획서를 작성해줘. |
| 화장품 규제·표시 검토 | [regulatory-labeling.md](regulatory-labeling.md) | 첨부한 패키지와 상세페이지 문구를 검토해줘. |
| 크리에이티브·디자인 | [creative-design.md](creative-design.md) | 브랜드 전략을 바탕으로 패키지 콘셉트를 제안해줘. |

| 손익·재고 분석 | [profit-inventory.md](profit-inventory.md) | 제공한 원가와 견적으로 채널별 손익과 발주량을 계산해줘. |

## 협업 흐름

시장 조사 → 브랜드 전략 → 상품 기획 → 손익·재고 타당성 검토 → 디자인·콘텐츠 제작 순서를 기본으로 한다. 규제·표시 검토는 제품 기획부터 문안 확정까지 반복한다. 제조 견적·재고·규제 결과에 따라 앞 단계의 가정을 갱신한다.

역할 간 전달 시 목표, 확정 사항, 출처, 가정, 미결 질문, 필요한 결과물을 함께 전달한다. 관련 설치 스킬이 있으면 그 지침을 따른다. 웹·이미지·데이터 도구의 실제 가용성을 확인하며, 역할 파일을 저장했다고 도구나 외부 서비스가 설치되지는 않는다.
